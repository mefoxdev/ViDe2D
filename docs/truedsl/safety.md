# Безопасность TrueDSL

В ViDe2D вы запускаете игры, которые написали другие люди: скачанные из ViDe-store, полученные по локальной сети (турниры), присланные другом. Поэтому безопасность заложена в сам язык, а не добавлена сверху. Эту страницу можно читать как обещание: что бы ни было написано в игре, она не сможет навредить вашему компьютеру.

> Версия спецификации 0.1 (черновик). Числа лимитов — значения по умолчанию, они могут быть уточнены до версии 1.0.

## Главный принцип: в языке нет опасных возможностей

В TrueDSL **нет** команд для:

- чтения и записи файлов по произвольному пути;
- доступа в интернет и к сети;
- запуска программ и работы с системой;
- чтения времени компьютера, имени пользователя, переменных окружения;
- подгрузки чужого кода (`eval`, импорт библиотек, нативные модули).

Всё, что скрипт может, — это работать с **игровым миром**: объекты сцены, ввод (клавиши, мышь), звук, переход между сценами и маленькое **личное хранилище игры** (`remember` / `recall`). Если возможности нет в языке, обойти это невозможно: у скрипта просто нет к ней доступа.

## Что скрипту доступно

| Область | Как | Ограничения |
|---|---|---|
| Картинки, звуки, сцены, скрипты | только файлы внутри папки своей игры: по имени файла или по относительному пути от папки проекта | пути с `..`, абсолютные и символические ссылки запрещены; размеры файлов ограничены |
| Другие скрипты | `use "file.tdsl"` внутри проекта | только действия `to`; путь внутри проекта |
| Сохранения | `remember` / `recall` | отдельное хранилище на каждую игру; другие игры его не видят и не могут прочитать |
| Ввод | клавиши и мышь внутри окна игры | клавиши вне окна игры не читаются |
| Сеть | в версии 0.1 нет | позже — только через ViDe2D Local Server (VLS), по явному разрешению и без «сырых» соединений |

## Ограничения ресурсов

Движок не даёт скрипту съесть все ресурсы компьютера. При превышении лимита останавливается только виновный обработчик, игра продолжает работать, а в консоль выводится понятное сообщение (см. [Ошибки](errors.md)).

| Что | Лимит по умолчанию |
|---|---|
| шаги выполнения за кадр (на всю игру) | 200 000 |
| шагов в одном запуске обработчика | 50 000 |
| глубина вложенных вызовов `to` | 64 |
| живых объектов, созданных через `spawn` | 5 000 |
| элементов в списке | 100 000 |
| длина текста | 10 000 символов |
| записей в `remember` | 1 000 ключей, 1 МБ суммарно |
| сообщений, отправленных за кадр | 1 000 (и не больше 5 000 ждущих доставки) |
| одновременных звуков | 32 |

Бесконечный цикл `while yes` без `wait` просто упрётся в лимит шагов, и обработчик будет остановлен.

## Повторяемость (детерминизм)

Игра на TrueDSL ведёт себя **одинаково при одном и том же вводе**:

- обновление идёт с фиксированной частотой 60 раз в секунду, независимо от скорости компьютера;
- порядок объектов и обработчиков строго определён (см. [справочник](reference.md#8-события-when));
- числа считаются одинаково на всех машинах;
- `random` использует зерно, которое движок может зафиксировать.

Это даёт честные турниры в локальной сети, записи повторов и воспроизводимые баги.

## Проверка до запуска

Скрипт проверяется **до** запуска игры (в VCode, при сборке и при публикации в ViDe-store):

- неизвестные имена, повторные объявления, неверные отступы;
- `wait` там, где он запрещён;
- очевидные ошибки типов (число вместо да/нет и т. п.);
- пути к файлам.

ViDe-store повторяет эту проверку при публикации и отклоняет пакеты, которые её не проходят.

## Что может случиться в худшем случае

Если кто-то нарочно напишет вредный скрипт, он сможет:

- сделать свою игру скучной, зависшей или сломанной;
- заполнить экран объектами — до лимита в 5 000;
- записать в своё хранилище до 1 МБ данных.

Он **не** сможет: прочитать ваши файлы, отправить что-то в интернет, повлиять на другие игры, запустить программы, обойти лимиты или остановить ViDe2D.

## Для авторов игр

- Не вставляйте в игру чужой скрипт, не прочитав его, — но вы можете делать это без страха за компьютер: худшее, что случится, — игра будет вести себя странно.
- Ошибки в вашем коде не роняют игру целиком: ошибочный обработчик останавливается, остальная игра работает.
